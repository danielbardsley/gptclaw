# Release record

- Observed at / repository / reviewed contract revision:
- Mode and requested scope:
- Candidate: source revision, proposed/actual version, immutable artifact, provenance.
- Evidence: actual build/tests, release notes; unknowns and supplied reports labeled.
- Target: environment, pipeline identity, current/prior deployed artifact.
- Authorization: exact artifact/target/operation, source and any outstanding protected gates.
- Readiness: health criteria, data compatibility, backups, recovery procedure and owner.
- Action: actual dispatch and run ID, or none; observations/deadline and sanitized links.
- Acceptance: deployed identity, health/data checks and outcome, separately from pipeline status.
- Recovery: authorized scope or proposal; actual run and verified result, if performed.
- Next action and owner: unresolved facts, outstanding run ID and required rechecks.

Keep preparation, authorization, submission, waiting, failure, deployed-unverified,
acceptance, recovery-needed and recovery verification distinct. Use only relevant
fields; never present a proposed step as an executed result.
