# Preview delivery checks

Resolve exact source revision and relevant dirty-work limitations, project/profile,
toolchain pins and existing local/EAS commands from project-owned documentation.
For a cloud path inspect the actual proposed archive before upload: mobile/workspace
inputs only as required; no environment/auth/signing files, runtime secrets,
private evidence, caches or unrelated backend data. Public compiled endpoints
must name the intended private development services and contain no credentials.
Verify private artifact access and development signing separation.

Before authorized submission record intended inputs and existing pending builds.
Submit once; retain the service/build ID, observe within documented bounds and
resume by that ID. Queued/running/failed/unknown are not success. Do not cancel
other builds or submit a replacement merely because observation times out.

For a finished artifact record the immutable source/build identity, APK SHA-256,
package, version code, ABI/native dependencies, bundled endpoint configuration
and signing certificate using the existing verifier. Refuse mismatched source,
artifact, target endpoint or signing identity; do not silently rebuild/retarget.
If a preview override exists, record its approved scope/expiry without extending it.

Verify installed package/certificate/version and migration compatibility before
in-place upgrade. Keep application data; no uninstall/storage-clear recovery.
Confirm installed version and open the principal journey. Record its actual outcome,
including a reopened persisted result when relevant, and any native failures.
Device work needs an available reviewed target. No production credentials, store
submission or public download sharing is implied.
