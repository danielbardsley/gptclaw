# Acceptance evidence outline

Authoring aid: record status, owner, evidence date, specification/design/tasks
links, tested revision, and PR/merge references when known. Unknown provenance
stays explicitly unknown. Creating this record does not declare acceptance.

## Criterion mapping

| Criterion | State | Evidence or limitation | Remaining action and owner |
|---|---|---|---|

Use passed, failed, pending, or not applicable with a reason. Include every
criterion. Cite actual artifacts/check outcomes; attribute supplied reports.

## Verification

Record exact executed commands, environment/context, revision and result.
Distinguish local checks, CI, deployed behavior, and owner acceptance. Record
skipped checks and reasons. Preserve failures and explain any corrective rerun.
Do not include credentials, authentication files, environment dumps, or real
sensitive datasets.

## Remaining work and delivery

Record unresolved failures, pending verification, operator actions, and relevant
rollback/cleanup limitations. Record merged implementation only when verified;
update catalogue completion only when merge and required acceptance are proven.
